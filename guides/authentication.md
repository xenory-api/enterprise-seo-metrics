# Authentication

This guide explains how to authenticate requests through RapidAPI.

All requests require a valid RapidAPI API key and the appropriate request headers.

# Overview

The Enterprise SEO Metrics API is distributed through **RapidAPI** and uses RapidAPI Authentication.

Every request must include:

- A valid `X-RapidAPI-Key`
- The HTTP Host request header
- The appropriate `Content-Type` header

Requests missing any required authentication headers will be rejected by the RapidAPI gateway before reaching the API.

# RapidAPI Applications

When you subscribe to the API on RapidAPI, your requests are associated with a **RapidAPI Application** (App).

An App is a virtual project that groups your API integrations and provides a single API key for authentication.

Using Apps allows you to:

- Use one API key across multiple RapidAPI services
- View request analytics and usage statistics
- Monitor response times and error rates
- Organise separate software projects under different applications

Example:

| Property | Value |
|----------|-------|
| App | `default-application_12031254` |
| Authentication Header | `X-RapidAPI-Key: YOUR_API_KEY` |
| RapidAPI Website | `https://rapidapi.com` |

RapidAPI automatically creates a default application when you create an account, although additional applications can be created from the RapidAPI Developer Dashboard if required.

# Obtaining an API Key

Your API key is generated by RapidAPI and is unique to your application.

To obtain your API key:

1. Sign in to your RapidAPI account.
2. Subscribe to the Enterprise SEO Metrics API.
3. Open your RapidAPI application.
4. Copy the generated API key.
5. Include the key in every request using the `X-RapidAPI-Key` header.

Example:

```text
X-RapidAPI-Key: YOUR_API_KEY
```

If your API key is ever compromised, RapidAPI allows you to generate a new key and revoke the old one from your application's dashboard.

# Required Headers

Every request must include the following HTTP headers.

| Header | Required | Value |
|---------|:--------:|-------|
| `X-RapidAPI-Key` | Yes | Your RapidAPI authentication key |
| `X-RapidAPI-Host` | Yes | `enterprise-seo-metrics.p.rapidapi.com` |
| `Content-Type` | Yes | `application/x-www-form-urlencoded` |

# Example Request

```bash
curl --request POST \
    --url https://enterprise-seo-metrics.p.rapidapi.com/{endpoint} \
    --header 'Content-Type: application/x-www-form-urlencoded' \
    --header 'X-RapidAPI-Host: enterprise-seo-metrics.p.rapidapi.com' \
    --header 'X-RapidAPI-Key: YOUR_API_KEY' \
    --data url=google.com
```

Replace:

- `{endpoint}` with the endpoint you wish to call.
- `YOUR_API_KEY` with your RapidAPI API key.

# Protecting Your API Key

Your RapidAPI API key identifies your application and should be treated as confidential.

Recommended practices include:

- Never commit API keys to source control.
- Store keys in environment variables or secure configuration files.
- Never expose API keys in client-side JavaScript or public repositories.
- Rotate your API key immediately if you believe it has been compromised.
- Use different RapidAPI applications for development, staging, and production environments where appropriate.

# Authentication Errors

Authentication failures are typically caused by missing or invalid request headers.

| HTTP Status | Description |
|------------|-------------|
| `401 Unauthorized` | Invalid or missing API credentials. |
| `403 Forbidden` | Your subscription does not permit access to the requested endpoint. |
| `429 Too Many Requests` | Your application has exceeded its current rate limit. |

If authentication fails:

- Verify your `X-RapidAPI-Key`.
- Confirm the `X-RapidAPI-Host` header is correct.
- Ensure your subscription to the API is active.
- Check that all required headers are included in the request.
